2.3 文档导入生成：RAG 管线是标准答案
“上传 PDF/Word/Markdown → 生成题目”已经有可复用的工程范式，核心管线是：
文档解析 → 分块（chunking，段落感知 + 重叠）→ 嵌入（embedding）→ 向量存储 → 检索增强生成（RAG）→ 结构化题目输出
ai-study-copilot 的具体参数可以作为起点：PDF/Markdown/TXT 上传，段落感知分块（约 1400 字符，150 重叠），本地多语言嵌入（384 维），Supabase pgvector 配合 HNSW 索引，LLM 严格从检索到的原文段落出题并附带引用。Equalu8 则展示了 Python 侧的文档解析选型：PyMuPDF + pdfplumber 做文本抽取，Tesseract 处理扫描件 OCR，生成的题目“citation-locked”到源材料，避免脱离文档的幻觉。
对你来说，务实的选择是：
文档解析和 RAG 放在独立的 Python 服务中

Web 端通过 API 调用
，而不是强行用 TypeScript 全栈吃掉文档解析和算法。JasonOracle/tiku 的架构也是 FastAPI 承担后端 + AI Agent 命题，uni-app 承担 C 端跨端，与你的技术背景和需求匹配度较高。

四、风险提示
Agent 生成代码的质量边界
：Agent 可以高效生成 CRUD、API 路由、UI 组件和 RAG 管线样板，但 RAG 的检索质量、题目生成的幻觉控制、掌握度模型的有效性，仍然需要你用真实数据迭代 prompt 和评估指标。不要把“Agent 能写完”等同于“Agent 能写对”。
开源项目的冷启动
：题库类开源项目面临“没有题 → 没人用 → 没人贡献题”的循环。建议 MVP 阶段自带一批高质量种子题库（例如前端面试 300–500 题），用可玩性带动第一批用户，再引导贡献。AGPL-3.0 能保护项目不被闭源 fork 吞掉，但也可能让部分企业用户犹豫；如果未来需要商业双轨，提前在贡献协议中预留空间。
跨端不要过早抽象
：在只有 Web 端的时候，不要为了“未来 App”而把所有组件都做成跨端抽象层。PWA 先把 Web 体验做扎实，App 阶段用 Capacitor 包装时只需要处理少量原生桥接，远好于一开始就被 uni-app/Taro 的运行时约束绑住。

DSH 插件模型里值得直接借鉴的契约设计
DSH 的插件写法有一套清晰的硬契约，这套契约对刷题工具的插件系统设计有直接的参考价值。一个工具插件的最小形态是三步：声明
inject
依赖 → 在
apply
里注册工具 → 在
defineTool
中分别声明
parameters
、
output.schema
和
execute
。
几个关键设计点值得迁移：
-
1
依赖注入而非直接引用。
插件需要什么服务就在
inject
里声明，框架负责加载时序，插件不需要在
apply
里自己等待服务就绪。
对应到刷题工具，插件可以声明
inject: ['rag', 'wrongbook', 'scheduler']
，核心服务由宿主保证存在，插件只消费抽象接口。
-
1
输入输出的双向 schema 约束。
parameters
管入参，
output.schema
管出参，框架在
execute
之前自动完成类型、必填、字面量约束的校验；
execute
必须返回一个 canonical 值（无损 JSON、可冻结），不能返回散文让调用方自己解析。
这对“跨行业自定义”至关重要：行业插件扩展的是题型、判题规则、标签体系，但这些扩展必须在统一的 schema 边界内发生，否则错题统计和掌握度计算会失去可比性。
-
1
注册是 effect 式的，卸载即注销。
插件卸载时自动清理注册的工具，宿主状态不会被残留污染。
对于“随插随用”的自定义场景，这是保证稳定性的基础设施。
-
1
dsh-algo-trainer
还提供了一个架构上的务实示范：它没有把原项目的 Express/SQLite 直接搬进插件，而是用 DSH 原生的工具注册重建数据层，分析引擎写成
纯函数
（输入
SubmissionRow[]
，无 IO 依赖），数据持久化用 JSON 文件落到宿主目录。这种“核心逻辑无状态、数据层轻量适配”的做法，适合你首版的插件运行时——不需要一开始就设计复杂的插件沙箱。

建议的首版架构轮廓
综合以上，一个可行的首版架构是：
宿主（核心）
负责：插件注册与生命周期、题目/作答/错题的统一 schema、RAG 管线（解析 → 分块 → 嵌入 → 检索 → 出题，带引用和降级）、错题记录与错因分类、SM-2/FSRS 复习调度、知识点掌握度聚合。
行业插件包
负责：知识树/标签体系、题目扩展字段的 schema、行业特有题型的判题器、行业错因分类的扩展项、可选的检索策略偏好。插件通过类似
defineTool
的契约声明能力，通过
inject
消费核心服务，不重复实现 RAG 和错题统计。
本地持久化
首版用 SQLite 或 JSON 文件即可，与
dsh-algo-trainer
