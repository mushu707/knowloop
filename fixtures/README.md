# fixtures/

S1 用的测试题库。**不是产品内容，是测试夹具。**

| 文件 | 说明 |
|---|---|
| `questions.seed.json` | 20 道前端面试题（单选 12 / 多选 5 / 判断 3），挂在 12 个知识点上 |

由 `node scripts/gen-fixture.mjs` 生成。**不要手改这个 JSON**——改 `scripts/gen-fixture.mjs` 里的 `RAW` 数组再重新生成，否则 `id`（内容哈希）会和数据对不上，导入时会被当成新题。

## 它同时是 schema 的第一次压力测试

README 里说手写能暴露 schema 设计的缺口。这 20 道题里有 5 道是刻意挑出来让你审的，因为它们在试探契约的边界：

| # | 题型 | 在试探什么 |
|---|---|---|
| 1 | 单选 | 题干里带 ```js 代码块（多行 Markdown + 缩进）能否原样渲染 |
| 2 | 多选 | 5 个选项（上限 8）、3 个正确答案是否可以接受 |
| 5 | 单选 | 选项文本里有反引号和单引号，会不会在渲染时出问题 |
| 12 | 多选 | **全选即正确**（4 个答案全对）——这类题该不该允许？还是应该改成判断题 |
| 20 | 判断 | 题干只有一句话、没有解析，UI 留白会不会太空 |

## 需要你回答的一件事

审完这 20 道，回我三个问题中的任意异常即可：

1. 有没有哪道题**你想标两个知识点但只能标一个**的感觉？（字段允许 1–6 个，但你没用上说明提示不够）
2. 有没有哪道题**想加一个"易错提示"但没有地方放**？（那 `extensions` 或 `explanation` 的结构要调整）
3. 第 12 题那种"全选即正确"的多选题，在你的实际刷题体验里**算不算好题**？

三个问题都没有 → schema 可以定稿，进 S1。
